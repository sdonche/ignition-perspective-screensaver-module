# CLAUDE.md

Ignition 8.3 Perspective module with ONE component: the Idle Guard, a
screensaver for Perspective pages. Structure and conventions mirror Mustry Doom
(Gradle + io.ia.sdk.modl, React 16 class component + TypeScript strict on the
web side, Java scopes for registration). README.md is the product page;
docs/reference.md holds the engineering detail (architecture, props, build,
tests, differences from docs/product-spec.md). Keep new technical detail
there, not in the README.

## Safety rules — non-negotiable

- An active Critical alarm is never covered, whatever the props say
  (`evaluateAlarms` clamps the wake priority; tested in jest and e2e).
- No feed, no cover: a stale or missing alarm feed removes the overlay and
  prevents idling (fail open). Never add a code path that shows the overlay
  without a fresh feed.
- The input that wakes the page must never reach the page. Wake listeners are
  window capture-phase; the rest of the gesture is swallowed for SWALLOW_MS
  while the overlay fades. If you touch this, run the e2e click and key tests
  AND check they still fail with swallowing disabled (mutation check: break
  the two `if (this.shielding ...)` conditions, set FADE_MS to 0).
- Never market or document the guard as an access control or a safety
  function. It is a browser overlay.

## Layout

- `web/typescript/components/guard/` — `idleLogic.ts` (pure, node-tested:
  state machine, alarm policy, night window, reduced motion, burn-in
  helpers), `guardProps.ts` (PropertyTree → props), `guardDelegate.ts`
  (store delegate, feed parsing), `IdleGuard.tsx` (the component: lifecycle,
  input, state, outputs), `Cover.tsx` (what is shown while idle),
  `CanvasMode.tsx` (canvas host), `modes/` (`modeToShow.ts` decides the
  shown mode: night > shuffle > reduced motion; canvas renderers: `gl/` holds
  the WebGL2 modes and post-processing; `fun/` the 2D funny modes;
  `pipes.ts` / `starfield.ts` are the 2D fallbacks; every `*Sim.ts`,
  `quality.ts`, `lineStyle.ts`, `haloLayout.ts` and `shuffle.ts` are pure and
  tested).
- A new canvas mode: add it to `MODES`, `CANVAS_MODES` (and `GL_MODES` if
  it has a GL renderer) in `guardProps.ts`, the factory in `modes/index.ts`,
  the schema enum, and the e2e `CANVAS_MODES` table with a measured threshold.
- Burn-in: nothing static may sit on the same pixels for hours. Text drifts
  (`drift()`), fixed layouts (pong's field) wander a little.
- Defaults stay calm: `clock` by default, the night window on (blank). The
  e2e suite pins the browser to a midday time zone (`e2e/clockZone.ts`) so the
  window never interferes; the night test picks a 1 a.m. zone.
- Visual work: `cd web && npm run preview`, open
  `web/build/preview/index.html#<mode>`; screenshot it headless rather than
  rebuilding the module each time. Then confirm on the gateway.
- GL modes must keep working without WebGL2 (2D fallback) and must not log
  console errors (the e2e fixture fails on them; a warning is fine).
- `common/` descriptor + `idleguard.props.json` + event schemas; `gateway/`
  hook, `AlarmFeed` (one poller per gateway), `GuardModelDelegate`;
  `designer/` registers the palette entry.
- Component identity must match in `IdleGuard.COMPONENT_ID` (Java) and
  `COMPONENT_TYPE` (TSX). Event names in `guardDelegate.ts` and
  `GuardModelDelegate.java` must match.
- The schema's defaults and `mapGuardProps` defaults must agree (guardProps
  test covers the mapper side).

## Verify project

`ops/verify/project` is bind-mounted into the dev gateway. Views and page
config are GENERATED by `ops/verify/tools/build_views.py`: edit the script,
rerun it, commit the JSON. The gateway only picks up project file changes on
restart (`docker restart mscreen-ignition`, or `ops/deploy.sh`). Tags come
from `screensaver.setupTags()` (project library), called from the Overview
view's onStartup. Alarm tests share gateway-wide tags: clear them first and
last.

## Build & verify

```bash
./gradlew build                 # .modl + jest + JUnit
cd web && npx tsc --noEmit && npm test
ops/fresh.sh                    # unattended dev gateway on :9388
ops/e2e.sh [--fresh|--no-deploy] # Playwright suite; PW_CHROMIUM_PATH=... without `playwright install`
```

Never call a change done because the build is green: open
http://localhost:9388/data/perspective/client/verify/test/pipes/5, wait, see
the pipes, move the mouse, see the page. Check the console is clean.
